ARCHITECTURE NOTES:
===================

Database Design:
  - research_sessions: Main container for a research task
  - plan_steps: Individual steps in the plan (ready for agent integration)
  - findings: Results from agents with confidence/relevancy scoring
  - Extended user_settings: For future API key management per user

Backend Flow:
  POST /sessions                    → Create session
  POST /sessions/{id}/plan          → Trigger DeepSeek planning
  GET  /sessions/{id}               → Poll session (finds plan + findings)
  GET  /sessions/{id}/findings      → Get findings list
  POST /sessions/{id}/findings/select → Mark findings as selected
  POST /sessions/{id}/generate-script → Create script from selections

Frontend Flow:
  / (homepage)
    ↓
  /research/[sessionId] (plan display + findings selection)
    ↓
  /research/[sessionId]/style (methodology picker)
    ↓
  /research/[sessionId]/results (final script)
